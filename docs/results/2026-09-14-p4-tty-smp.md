## Diagnosis

- FXRSTOR raises #GP for a misaligned operand or for reserved bits in the
  MXCSR image (SDM vol. 2A, FXRSTOR, protected mode exceptions). The operand
  was 16-byte aligned, so the image was the problem: both fpstates carried
  the mainline default `MXCSR_DEFAULT = 0x1f80`.
- The recovery path made it fatal: `ex_handler_fprestore` (arch/x86/mm/extable.c)
  FXRSTORs `init_fpstate`, which holds the same image, so the #GP recurred
  inside the #GP handler until the task stack guard page was hit.
- Intel's k1om tree (`vendor/solros/phi-kernel`, reference only) documents
  the hardware rule: `arch/x86/include/asm/i387.h`, `fxrstor_checking`,
  "KNC errata: MXCSR.DUE (bit 21) must be 1. Force it on here";
  `arch/x86/kernel/i387.c`, `mxcsr_feature_mask_init`, loads `1 << 21` with
  `ldmxcsr` on every CPU ("Must set DUE (bit 21) to avoid GP# on vector
  register access") and ORs the bit into the feature mask; the same file's
  fpstate init starts every K1OM task with `mxcsr = 1 << 21` ("Otherwise any
  future fxstore will result in GP fault"). The SSE exception-mask bits of
  `0x1f80` are not set in Intel's card image because the card has no SSE.

## Fix: kernel patch 0018

Under `CONFIG_X86_KNC`: `MXCSR_DEFAULT` is `0x200000`
(`arch/x86/include/asm/fpu/types.h`); `fxrstor()` and `fxrstor_safe()`
(`arch/x86/kernel/fpu/legacy.h`) set the bit when an image lacks it, without
writing an image that already has it (`init_fpstate` is read-only after
init); `fpu__init_cpu_generic` loads the default on every CPU;
`fpu__init_system_mxcsr` admits the bit in `mxcsr_feature_mask` (signal
frames and ptrace) and logs the live MXCSR and the FXSAVE mask once. The
SIMD exception decoder's MXCSR local became `u32` so the constant fits (that
path needs X86_FEATURE_XMM and never runs on the card).

Consequence for user space: LDMXCSR with an image lacking bit 21 is expected
to fault the same way, and musl's `fesetenv(FE_DFL_ENV)` loads `0x1f80`
(`src/fenv/x86_64/fenv.s`). The card libc needs a DUE default environment;
tracked in `docs/plan.md` under P4.

## Also learned

- The tty output path carried the whole oops (about 60 lines of registers
  and traces) without loss at 10 ms input polling; the ring console write is
  sound in exception context.
- The bootstrap e820 has RAM at `0x50000..0x5ffff` and `0x80000..0xcffff`,
  enough for the SMP real-mode trampoline (test 5).

## Test 4b: a shell on the card (2026-09-14 17:43 UTC, kernel with patch 0018)

Same command, log in `~/phi-t4b.log` (297 lines). New line from patch 0018:

```
x86/fpu: KNC: MXCSR 0x200000 at boot, FXSAVE MXCSR mask 0x30e07f, DUE forced on
```

reports a non-zero mask (`0x30e07f`: flags, DAZ, the masks, FZ, plus bits 20
and 21), which is the mask the kernel now uses for user MXCSR validation.
