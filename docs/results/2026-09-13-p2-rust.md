# 2026-09-13: Rust `std` for the card and the full P2 exit check (Rust half)

Host: Arch/CachyOS, kernel 7.2.3-1-cachyos, 16 threads. Compiler: Arch
`rust 1:1.98.1-1.1` (rustc 1.98.1, 48a229cea 2026-09-01) with the patched
`libLLVM.so.22.1` (LLVM 22.1.8, patches 0001 to 0008) loaded through
`LD_LIBRARY_PATH`. Sysroot: musl 1.2.5, compiler-rt builtins, libunwind
22.1.8 (`toolchain/libunwind/build.sh`, new today).

## What was blocking, and how it was resolved

`toolchain/rust/build-std.sh` failed at target load: "target feature `sse2`
is required by the ABI but gets disabled in target spec". Read in rustc
1.98.1 (`rustc_target/src/target_features.rs`, `spec/mod.rs`,
`rustc_codegen_ssa/src/target_features.rs`, `rustc_codegen_llvm/src/llvm_util.rs`):

- The check inspects the literal feature names of the spec against
  `abi_required_features()` (`x87`, `sse2` required; `soft-float` forbidden).
- Reverse implication (`-sse` disables everything that implies `sse`) is
  applied afterwards, in both `cfg` and the backend feature list, and no
  step re-enables ABI-required features.
- `x86-softfloat` unconditionally requires `+soft-float` (option "C" from
  the resume note is dead).

So the spec now says `-sse` (never `-sse2`), rustc warns once per crate
and otherwise compiles through the patched backend. ADR 0007 records the
decision and the escape hatch; no rustc build was needed.

## Residues found on the way, each now a rule

| Residue | Where | Fix |
| --- | --- | --- |
| `panic_immediate_abort` rejected by `core` | `.cargo/config.toml` | Dropped: in 1.98 it is a panic strategy, not a cargo feature. Profile `panic = "abort"` plus the spec's `panic-strategy` suffice. |
| Undefined `_Unwind_*` at the final link | `std` backtrace printer, `unwind` crate links `libunwind.a` on static musl | `toolchain/libunwind/build.sh`: LLVM libunwind built with `knc-cc`, audit 0 illegal, 0 suspect (83 sections, 6565 instructions); `run.sh` adds `-lunwind`. |
| `rust_hypot=-1` although the staticlib was linked | weak stub in `hello.c` satisfied the linker, archive member never pulled | `hello.c` declares the real symbol under `-DHAVE_RUST` (set by `run.sh`) and checks the value (exit 3 on mismatch). |
| 10 `pause` (ILLEGAL) in the linked binary | `std` futex `Mutex`/`RwLock` spin loops, stack-overflow handler, via `core::hint::spin_loop` and the `llvm.x86.sse2.pause` intrinsic | LLVM patch 0008: the intrinsic selects `PAUSE` only with SSE2, otherwise a codegen-only one-byte `nop`. Same fix for C's `_mm_pause()`, verified: `spin()` compiles to `nop`; inline `asm("pause")` still assembles. |
| 1 `xgetbv` (ILLEGAL) in the staticlib only | `std_detect`, `core::arch::_xgetbv` behind CPUID.OSXSAVE | Not linked (gc-sections). `phi-isa-audit --ignore XSAVE` (new option) for the archive audit; linked binaries audited without exceptions. |

## Readings

- Phase P2's exit criterion is met: a static `hello` in C and Rust links,
  runs on the host, and audits clean. Rust and C share the knc64-x87 ABI
  because both are lowered by the same patched backend; rustc adds no ABI
  code of its own for scalars.
- The whole Rust side costs the dylib LLVM variant plus twenty seconds per
  `build-std`; no nightly, no rustup, no compiler build.
- Warnings are part of the expected output: one `sse2` ABI warning per
  crate. Silence would mean a newer rustc changed the rule (ADR 0007).
- `pause` was the first deletion-list instruction to reach a linked binary
  through a *compiler intrinsic* rather than hand-written assembly; the
  audit on the linked binary, not on archives, is what caught it.

## Clean rebuild (same evening)

Both LLVM variants were then rebuilt from scratch through
`toolchain/llvm/build.sh all` under the space-free paths (dylib 12 min,
clang 15 min on 16 threads). Two script defects surfaced and are fixed:
the build picked up the card clang as the host compiler once `env.sh`
put it first on `PATH` (now pinned to `/usr/bin/clang++`), and the dylib
variant ran the clang-only check step (now skipped for that variant).
With the clean pair installed, `build-std.sh` and `run.sh` reproduce the
results above unchanged.
