## The direct-access tool, from an unprivileged shell (uid 1000, no sudo)

| command | result |
| --- | --- |
| `phictl status` | `card agent 0.1.0 reachable through /run/phictl/control.sock` |
| `phictl exec -- nproc` | `228`, exit 0 |
| `printf 'alpha\nbeta\n' \| phictl exec -- sh -c 'wc -l; echo to-stderr >&2; exit 3'` | `2` on stdout, `to-stderr` on stderr, exit status 3 |
| `phictl put blob /tmp/blob` (300000 random bytes) | 32 ms; `md5sum` on the card equals the host's |
| `phictl get /tmp/blob blob.back` | 48 ms; `cmp` identical |
| `ls /run/phictl/` as the owner | permission denied (directory is root 0711 by design) |

Compile on the host, run on the card: a 228-thread Leibniz series
(`pi.c`, pthreads, x87 doubles) built with `knc-cc -O2 -static`, audited,
`put` and `exec`:

```
228 threads, 199999776 terms: pi = 3.141592649      (0.31 s wall, transport included)
```

The same binary on the host's 16 threads takes 0.03 s: the card's in-order
1.1 GHz cores are about ten times slower per thread on this x87 loop, as
expected.

## Network

`ping 10.9.0.2`: 3 of 3, 2.6 ms average through two 1 kHz polls. The bridge

## Two defects found and fixed

- init started `dropbear -s -E -p 22`; this build (no syslog) has no `-E`
  and dropbear exited with a usage message, so port 22 was closed. Started
  by hand through the tool with `dropbear -s -p 22` it listens and answers;
  init and the docs now use that line.
- `phictl exec -- sh -c 'dropbear -s -p 22; ...'` never returned: the
  agent waited for the command's output pipes to close, and the daemonised
  dropbear had inherited them. The agent now gives the output pumps 300 ms
  after the command exits and then abandons them (later output from a
  background process is discarded). The running card still has the old
  agent, so the fix takes effect on the next boot.

## Test 12: a stop after the topology lines, and a 471 MB log

Same command, kernel 0022, host commit `bfd80bb`. The kernel stopped right
after `CPU topo: [Firmware Bug]: APIC enumeration order not specification
compliant` (POST stayed at `K3`; the next action is the SBOX I/O APIC
register read in `mp_register_ioapic`), while the host's bridge and relay
threads were already active. The console tail then looped over the ring
(the intact text block followed by the ring's unwritten zeros, 305 times)
until stopped by hand: 471 MB in about a minute.

Fixes (commit `cb3db01`): the ring consumer resynchronises to the
producer's head when the indices disagree by more than a ring (unit
test); the `--net` bridge and `--serve` relay wait for POST `K7` before
touching card memory; kernel patch 0023 no longer registers the SBOX I/O
APIC (unused so far, version register reads 0, and the read sits at the
point of the stop). Which of the three mattered is not settled by one
boot; all three are worth keeping.
