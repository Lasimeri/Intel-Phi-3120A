# 2026-09-16: autoboot at login and access hardening

Superseded in one respect on 2026-09-19: the card now starts at **host
boot** and keeps running with nobody logged in, so the release-on-last-
session behaviour described below is no longer what happens by default
(`2026-09-19-boot-without-login.md`; `phi-autoboot.sh at-login` restores
it). Everything about the access model here still holds: what changed is
how long the card is reachable, not by whom.

- `scripts/phi-autoboot.sh install /mnt/1TB-NVMe/phi/disk.img` writes and
  enables `~/.config/systemd/user/phi.service` (wanted by
  `default.target`): the card boots when the user's session starts, with
  the control socket, the SSH forwarder on 127.0.0.1:2222 and the
  persistent disk, and halts cleanly (power off through the socket, then
  release) when the last session ends or on `systemctl --user stop`.
- The card's SSH host key is pinned (`~/.ssh/known_hosts_phi`,
  `StrictHostKeyChecking yes` for `Host phi-fwd`), the initramfs image is
  mode 0600 (it carries the host keys), the disk image is 0600, the
  forwarder was already loopback-only and the control socket owner-only
  with peer credential checks. The model is written up in
  `docs/howto/secure-access.md`.

Verification: see the commands and outputs recorded in the commit that
added this file (service active, `phictl status` answering, `ssh phi-fwd`
connecting with the pinned key, a `systemctl --user restart` bringing the
card back).
