## Readings

1. **The POST register is live and is an ASCII pair, low byte first.**
   The characters match Intel's MPSS 2.1 table including its mixed case
   (`"3C"` upper, `"3d"` lower, `"0F"` upper, `"0c"` lower), which means
   that table was transcribed from this register.
2. **Reset takes effect about 200 ms after the `RGCR` write.** The device
   disappears from the bus for one sample (`0xffffffff`, all-ones MMIO
   read) and comes back at `"0c"`.
3. **`"0c"` precedes memory training on this firmware.** So the `"0c"`
   seen at first contact, with `SPAD2` already flagged ready, means the
   bootstrap had re-run its early stages after reaching ready at host
   power-on, or the register was never advanced past `"0c"` on that run.
   Not explained by the documents; watch whether it recurs after a host
   reboot. It has no operational consequence: `SPAD2` bit 0 is the ready
   signal Intel's driver used, and it agreed with `"12"` here.
4. **GDDR training runs in full on every reset** (7.4 s, from `"30"` to
   `"3F"`); the `"32" Find GDDR training parameters in flash` step never
   appears. Either this flash stores no parameters or the sequence
   differs on this firmware. Budget 10 s per reset.
5. **`"16"` is not in Intel's table.** It sits between GDDR finalize and
   "Enable caching"; the table has `"15" Report platform information` and
   `"17" Page table setup`, so `"16"` is plausibly a platform-information
   substep. Recorded as observed, undecoded.
6. **Phase P1 exit criterion met:** after reset, POST code `"12"` and
   `SPAD2` bit 0 = 1, download address 64 MiB, BSP APIC ID 224.
