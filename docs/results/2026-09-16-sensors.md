# 2026-09-16: sensors and performance counters

## Sensors

Two readers of the same SBOX registers, decoded as Intel's RAS module
for the card does (MPSS 3.8.6 `ras/micras_knc.c`, reference only):

- On the card, kernel patch 0027 (`knc_hwmon.c`) registers hwmon `knc`:
  `temp1..temp9` die sensors, `temp10..temp15` inlet, VCCP regulator,
  GDDR, GDDR regulator, VDDG regulator and the TMU's die reading, `in0`
  core voltage, plus `core_mhz`, `core_ratio_mhz` and `raw`. lm-sensors
  and psutil (glances) read them from sysfs.
- On the host, `phictl sensors` asks the daemon, which reads the SBOX
  through the MMIO BAR; the card is not involved, so it answers while the
  card boots or hangs.

What this 3120A reports:

| reading | value | note |
| --- | --- | --- |
| die temperatures | 7 sensors, 47 to 53 C idle | sensors 8 and 9 read 0 (unfused), shown absent; maxima seen 63 to 66 C |
| core voltage | 1100 mV | SVID code 0xab, VR12: 250 mV + 5 mV per step |
| core clock | 1100 MHz | COREFREQ 0x416: feedback 11, feed-forward 2, 200 MHz base; CURRENT_CLK_RATIO reads 0 on this card, so the platform layer (patch 0027) now decodes COREFREQ when CLK_RATIO is 0 and the boot log no longer reports an assumed clock |
| board temperatures, VDDG, TMU | absent | the SMC broadcasts them only to a driver that asks (MPSS's I2C path); this port has none |
| power | not available | same reason: the SMC holds the power telemetry |

Under load (four 8K Mandelbrot renders at maxiter 4000 on 228 threads,
about 20 s): die sensors rose from 53 to 59 C, back to 57 C five
seconds after. A passively cooled card living on the chassis airflow.

## Performance counters

The kernel's Knights Corner PMU driver is active (`Performance Events:
knc PMU driver`), so `perf_event_open` works. `card/examples/phiperf.c`
is a `perf stat` for the card (the perf tool is not built): the six
generic events multiplexed on the core's two counters, or raw KNC
events, around a command and its threads.

`phiperf ./mandel out.png 1920 1080 2000 228` (x87 loop, 228 threads):

| event | count | share of time counted |
| --- | --- | --- |
| cycles | 56.0 G | 33% |
| instructions | 13.7 G | 33% |
| cache references | 1.19 G | 33% |
| cache misses | 10.6 M | 33% |
| branches | 948 M | 33% |
| branch misses | 42.4 M | 33% |

Instructions per cycle 0.24 per hardware thread: four threads share one
in-order pipeline, so this is the pipeline full. With eight events the
multiplexed estimates get rough (`-n` counts only the raw events given,
exact for two). Raw L2 events on the same run: 4.7 M read misses
(0x10cb), 6.3 M write hits (0x10cc).

## What is still open

Power readout and the board sensors need the SMC over I2C (the RAS
module's path); the fan is not the card's business on a passive 3120A.

## Correction (2026-09-17)

"CURRENT_CLK_RATIO reads 0 on this card" was true of the offset this port
read, 0x3004, which is the Knights Ferry offset: the merged MPSS
`micsboxdefine.h` lists it without a generation guard. Intel's k1om tree
(`mic_knc/micsboxdefine.h` `SBOX_CURRENTRATIO`, `intelmic.c` under
`CONFIG_MK1OM`) puts the KNC register at 0x402C, and that one reads
`0x04160416` here: current and goal ratio `0x416`, 1100 MHz, the same as
`COREFREQ`. `phi-regs`, the platform layer and the hwmon driver (patch 0027,
re-exported) now read 0x402C; `core_ratio_mhz` reports 1100 and the
`COREFREQ` fallback in the platform layer remains as a second source
(`docs/spec/sbox-registers.md` has the measured words).
