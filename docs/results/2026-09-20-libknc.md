# 2026-09-20: libknc, and the card at 0.41x the host on FastLanes decoding

`docs/results/2026-09-20-bitunpack.md` established that hand-written MVEX
bit-unpacking is worth 46 to 58x the card's own scalar code. This is the
follow-through: every width, both directions, packaged as a library, and
measured against the host doing the same job the way FastLanes intends.

## What was built

`card/lib/knc`: `libknc.a` plus `knc.h` and `knc.hpp`, installed into the
host sysroot for `knc-cc` and into `/opt/phi/usr` for the card's own clang,
so `cc prog.c -lknc` works in both places. 64 kernels, widths 1 to 32, pack
and unpack, plus the block copy.

No C and no Rust inside it. The kernels are generated assembly and the
width dispatch is two tail-calling thunks the generator emits, so the
archive pulls in no runtime and cannot collide with musl, libc++, CPython
or QuickJS when it is linked into them.

## Conformance

`knc_test.c` on the card, first run: **0 checks failed**, all 32 widths,
three crossings each. A round trip alone would prove nothing (pack and
unpack share an idea of the layout and would agree even if it were wrong),
so each direction is also crossed with an independent scalar model, and the
packed bytes are compared with the model's byte for byte.

## Throughput, 11 bits, decode

Millions of values per second. `stream` is a contiguous bitstream scalar,
the way a codec ordinarily does it. `lanes` is scalar over the interleaved
layout, which is **FastLanes' own method**: the compiler auto-vectorises it
where it can. `libknc` is the hand-written MVEX.

Card: Xeon Phi 3120A, 57 cores, 228 threads, 1.1 GHz, clang 22.1.8 with the
project's `-mno-*` set. Host: 16 threads, AVX2, the same C++ source at
`-O3 -march=native`. `card/lib/knc/lanes_bench.cpp` is that source, and it
is deliberately the same file on both machines so the only variables are
the machine and its compiler.

## Readings

**libknc saturates the card's memory bandwidth.** 12556 M values per second
at 11 bits moves 4 bytes out and 1.375 in per value, about 67 GB/s, against
the 66.0 GB/s `card/examples/membw.md` measures at 228 threads. The kernels
have no throughput left to give; only moving less data would help, which is
an argument for cascading (delta, FOR, dictionary) rather than for faster
unpacking.

**0.41x the host, the best ratio this project has measured.** xz reached
0.22 to 0.26, zstd 0.03 to 0.07, scalar integer work 0.14, scalar float
0.25. The only figure above 1 remains memory bandwidth (2.25x) and the
Mandelbrot VPU kernel against AVX2 (1.47x), both of which are narrower
claims than this one.

It is still a loss. 228 threads at 1.1 GHz against 16 threads, and the host
wins by 2.5x.

**The vector unit is exactly what closes the gap.** Card scalar against host
scalar on the same layout is 6355 against 30836, 0.21x. libknc doubles that
to 0.41x. Per thread it is worth 4.4x over the card's best scalar code and
10.7x over the ordinary bitstream layout.

**Pack costs about what unpack does.** 15586 M values per second against
12556 at 228 threads, 11 bits. That was not obvious: packing is an or-chain
per output word where unpacking is independent per value, and it needed a
different emission strategy (word-major, four words in flight, two partial
accumulators each) to get there.

## Corrections to the earlier document

`2026-09-20-bitunpack.md` reported the interleaved layout as a *loss* in
scalar, 24 to 27 M/s against a contiguous bitstream's 42 to 52. That was a
bad baseline: the implementation looped over values and recovered the lane
and position with a divide and a modulo each time, measuring the traversal
rather than the layout. Written position-outer, lane-inner, which is how
FastLanes writes it, the same data decodes at 118 M/s. Both documents are
corrected; the 46 to 58x headline is unaffected because it compares against
`stream`, which did not change.

A second bug, in `phi-isa-audit`: `mvex_length` gave an immediate byte only
to the 0F3A map and to `vcmppd`, so the new `72 /digit ib` shifts decoded
one byte short, the disassembler lost sync, and the first audit of
`libknc.a` reported 177 illegal instructions that did not exist. Fixed by
adding `70` and `72` to the 0F map's immediate rule, with the byte
sequences from the hardware-verified probe as the test.

## What is still open

A cascading codec. Bit-packing alone is the bottom layer; FOR, delta,
dictionary and RLE are what make columnar compression competitive, and they
are the same instruction set (`vpsubd`, `vpaddd`) on the same layout.

The 0.41x is decode of an already-packed block. End to end a codec also
reads and writes, and this card's link to the host is a Gen2 x8 slot.
