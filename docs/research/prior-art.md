# Prior art

| Project | What it is | What this project takes from it |
| --- | --- | --- |
| Intel MPSS 3.8.6 (2019, last KNC release), archived at archive.org item `intel-mpss-3.8.6` (`mpss-3.8.6-linux.tar`, `mpss-3.8.6-k1om.tar`, `mpss-src-3.8.6.tar`, `mpss-downloadcache-3.8.6.tar`) | Host driver `mic.ko` (GPL), `mpssd`, `micctrl`, card boot files, k1om cross toolchain | SBOX register headers, boot files for the oracle VM, `mpssd` command-line generation as reference. Read only. |
| Mainline `drivers/misc/mic` (Linux 3.13 to 5.9; removed in 5.10) | Intel's second host driver generation, cleaner than `mpss-modules` | Register offsets, the boot sequence (`mic_x100.c`), SMPT geometry. Everything in `docs/spec/sbox-registers.md` cites it. |
| `mpss-modules` forks: subgeniuskitty/xeon-phi-kernel-module, charlieporth1/mpss-modules (5.4), jjkeijser/mpss (CentOS 7.9/8.5, Ubuntu 18), CIRCL/mpss-modules (3.19), huanzhang12/mpss-modules (4.2) | Keep Intel's C driver compiling on newer host kernels | Evidence that the kernel-module route is a treadmill; reason for decisions/0001. |
| Xeon Phi Revival Project (github.com/Xeon-Phi-Revival-Project/xeon-phi-revival, 2026, MIT) | XPR-OS 0.1.0-rc6: rebuilt Intel 2.6.38 k1om kernel plus five MIC modules, new init, Dropbear SSH, Python 3.12 userland, validated on a 5110P under an MPSS 3.4.10 host. Extensive documented evidence of the k1om ELF/ABI, stock uOS inventory, toolchain feasibility. | Confirms the k1om SDK toolchain still works; confirms that a new userland boots under Intel's kernel; located the Intel kernel source. Their path keeps MPSS on the host and Intel's kernel on the card, which is the opposite of this project's goal, so nothing is imported. |
| `cosmoss-jigu/solros` (EuroSys 2018 "SOLROS" research OS) | Contains `phi-kernel`: a complete `linux-2.6.38.8+mpss3.5.1` tree with `arch/x86/kernel/intelmic.c`, `asm/mic_def.h`, `configs/k1om.uconfig` | The reference diff for the forward-port. Fetched into `vendor/`, never copied. |
| Linux `arch/x86/events/intel/knc.c` | KNC PMU support, in mainline since 3.7 (Vince Weaver) | Still present on master; `perf` will work on the ported kernel. |
| PyPhi (bpartridge), PythonForMIC (jphalimi), python-dev thread "python3 k1om" (2016), Intel forum "Got to work Python as a native application" (2013) | CPython 2.7 and 3.4 cross-builds for k1om with ICC; libffi needed a zmm-ABI patch for `ctypes` | Confirms CPython has no other KNC blockers; libffi is the one ABI-sensitive component, patched for this project's ABI instead. |
| LLVM-dev 2013 "LLVM x86 backend for Intel MIC" (Dmitry Mikushin) | Scalar-only `k1om64` LLVM patch; observation that KNC has no xmm registers so standard 64-bit binaries are "partially incompatible" | Confirms scalar LLVM codegen for KNC is a small delta. |
| Intel community thread "Are there any instructions in k1om can replace lfence" | Users stripping fences to build for KNC | Corroborates fences as unsupported. |
| Intel community "Knights Corner" ISA thread (2012) | Community reading of the ISA manual: "misses MMX, SSE, AVX, and other things like CMOV" | Corroborates CMOV. |
| Kitten lightweight kernel (kitten-commits, 2013) | Kitten was cross-compiled for KNC | Evidence a non-Intel kernel has booted on KNC. |
| jailhouse guest support in mainline (`arch/x86/kernel/jailhouse.c`) | x86 platform with no legacy devices, CPU list and timing data from a setup structure | The template for the KNC platform layer. |
