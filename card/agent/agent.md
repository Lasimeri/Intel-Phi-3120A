# phi-agent

The card end of `phictl exec`, `put`, `get` and `status`, and of `phitop`'s
samples. It opens `/dev/phirpc` (kernel patch 0022, the ring's kind-3
channel as a byte stream) and serves rpc frames
(`host/crates/phi-rpc/src/lib.rs`) one session at a time:

- `Exec`: run the program with exactly the environment sent, pipes on all
  three standard streams; `Stdin` frames feed it until `StdinEof` or its
  exit, its output comes back as `Stdout`/`Stderr` frames, then `Exit`
  (exit status, or 128 plus the signal). `exec.S`, `exec.md`.
- `PutOpen`/`PutData`/`PutClose`: write the file with the requested mode,
  `fsync`, answer `Exit(0)` or `Error`. `Get`: the file as `GetData`
  frames, then `GetEnd { size }`. `xfer.S`, `xfer.md`.
- `Stat`: one sample of the card for `phitop`, answered in every state:
  outside a session, while a command runs, during a put or a get.
  `stat.S`, `stat.md`.
- `Ping`: `Pong { version }`, the version being `0.2.0` (the Rust agent was
  `0.1.0`, so `phi status` tells them apart).

Errors in a request answer with `Error` and end the session. Stray
`Stdin`, `StdinEof`, `PutData` and `PutClose` frames outside a session are
ignored (the daemon closes a departed client's input after the fact);
any other message outside a session is answered with `Error("unexpected
<name> outside a session")`. A frame that does not decode is logged and
dropped as phi-rpc's `Decoder` drops it (`wire.md`).

The agent runs as root on a RAM-only system that the host resets at will;
the security boundary is the daemon's socket on the host
(`host/crates/phictl/src/serve.md`, ADR 0008), not this program. `/init`
starts it once, without respawn, with its messages on the console, so
nothing the host sends may end it: only the device failing does (exit
status 1, "phi-agent: /dev/phirpc: <why>").

## Why assembly

Until 2026-09-29 this was Rust (`src/main.rs`, `src/stat.rs`, removed in
the commit that added these files). Building it needed the whole card
Rust path (ADR 0007): the patched `libLLVM.so` variant, `RUSTC_BOOTSTRAP`,
the `-sse` target-spec workaround that rustc warns about
(rust-lang/rust#116344), `build-std`, musl and libunwind. The agent is in
every boot image, so the boot path depended on all of that. In assembly it
needs GNU `as` and `ld` and nothing else, makes its system calls directly
(no libc, so no musl `fenv` question either), and every instruction in it
was chosen for Knights Corner rather than left to a backend: `phi-isa-audit`
finds nothing to flag (`host/crates/phi-rpc/tests/agent.rs`,
`passes_the_knc_audit`).

Measured on card 1 against the Rust agent, three interleaved rounds
(`docs/results/2026-09-29-agent-assembly.md`): 20 KiB instead of 536 KiB,
one thread instead of three, a `Stat` sample costs 14.7 ms of user time
instead of 68 ms, transfers are 5 to 21 percent faster, resident size
388 KiB instead of 836 KiB.

What changed in the design: the Rust agent pumped the command's output
from two threads and serialised frames with a lock; here one `poll(2)`
loop serves the device, the three pipes and a pidfd for the child. Frames
cannot interleave (one writer), and nothing can follow `Exit` because the
output pipes are closed right after it. The wire, the limits (32 KiB
output frames, 20 ms child polling, 300 ms output grace, 1 MiB input
backlog) and every message text are the Rust agent's.

## Files

| file | what |
| --- | --- |
| `agent.S` | `_start`: standard descriptors, SIGPIPE, arguments, the device; the frame loop outside a session |
| `wire.S` | the device reader (frames, validation), the frame writer, message names |
| `exec.S` | `Exec`: decoding, the environment, fork and exec, the command loop |
| `xfer.S` | `PutOpen` and `Get` |
| `stat.S` | the `Stat` sampler |
| `text.S` | the write cursor, logging, scanning, number parsing, UTF-8, file reading |
| `errno.S` | musl's error messages, generated by `errno.sh` |
| `defs.inc` | system call numbers, flags, wire constants, buffer sizes |

All routines follow the System V calling convention (arguments in `rdi`,
`rsi`, `rdx`, `rcx`, `r8`, `r9`; `rbx`, `rbp`, `r12` to `r15` preserved)
unless their comment says otherwise. There is no heap: buffers are `.bss`
(`defs.md` lists them), paged in as touched, so the agent's resident size
is what it last used.

## Arguments

None on the card. For tests on the host:

- `--device PATH` opens another device; `--device -` uses standard input,
  which the host tests make a socket.
- `--root DIR` prefixes every `/proc` and `/sys` path the sampler reads,
  so a fixture tree stands in for the card.

## Testing

`cargo test -p phi-rpc --test agent` (part of `make check`) builds the agent
with `build.sh --out`, runs it on the host over a socket pair, and checks
every verb, the error texts, bad frames, the environment order, a command
that leaves a child in the background, 3 MiB through `cat`, a `StatReply`
against a fixture field by field across six samples, and the audit. On the
card, `phi -c N status` shows `card agent 0.2.0`.
