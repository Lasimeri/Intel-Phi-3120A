# vpu_probe.c and vpu_probe.S

`vpu_probe.S` is generated by `knc-mvex-gen probe` (host/crates/knc-mvex)
and holds three functions of hand-encoded Knights Corner vector code:

- `vpu_probe(in, out, mask)`: loads two float64 vectors, runs `vaddpd`,
  `vmulpd`, `vfmadd213pd`, `vsubpd`, a register move through `zmm31`
  (exercises the R/R' extension bits), a masked `vaddpd {k3}` and
  `vcmppd` with the result moved to a general register by `kmov`.
- `vpu_set(area)` / `vpu_get(area)`: load or store all 32 zmm registers
  (64 bytes each, at offset 0) and the 8 mask registers (16 bits each, at
  offset 2048) from a 64-byte aligned area.

`vpu_probe.c` checks every lane of every result against scalar arithmetic
(exact equality; the inputs are chosen so that all results are exact).
Build on the card: `cc -O2 -o vpu_probe vpu_probe.c vpu_probe.S`.

Result 2026-09-15: all seven checks pass on the card, before any kernel
change: the vector unit executes from user space as soon as MXCSR.DUE is
set (patch 0018), which agrees with Intel's k1om tree (`i387.c`: "must
set DUE (bit 21) to avoid GP# on vector register access").
