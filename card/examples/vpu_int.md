# vpu_int.c and vpu_int.S

`vpu_int.S` is generated by `knc-mvex-gen int-probe` (host/crates/knc-mvex)
and holds one function, `vpu_int_probe(in, out)`, which executes exactly
one integer vector instruction per output slot: sixteen slots, sixteen
instructions, nothing fused.

```sh
phi put card/examples/vpu_int.c /tmp/vpu_int.c
phi put card/examples/vpu_int.S /tmp/vpu_int.S
phi run sh -c 'cd /tmp && cc -O2 -o vpu_int vpu_int.c vpu_int.S && ./vpu_int'
```

## Why it has to run on hardware

The float64 encodings in `knc-mvex` reproduce Intel's k1om kernel macros
byte for byte, so a mistake in them fails a unit test on the host. The
integer encodings have no such reference: their only source is the opcode
column of ISA reference 327364-001 chapter 6.

A wrong prefix bit almost never faults. MVEX is dense, so a flipped `W` or
a misplaced extension bit decodes as some other valid instruction and
returns plausible numbers. The check therefore has to be semantic, and it
has to run here. `vpu_int.c` computes every lane of every slot in scalar C
and compares exactly.

## What each slot covers

| Slot | Instruction | What it is there for |
| --- | --- | --- |
| 0, 1 | `vpaddd`, `vpsubd` | The `NDS` three-operand shape at `W0`. `vpsubd` is not commutative, so it pins operand order |
| 2 to 5 | `vpandd`, `vpandnd`, `vpord`, `vpxord` | The bitwise set. `vpandnd` is `(!zmm2) & src`, which pins operand order again |
| 6 to 10 | `vpslld`, `vpsrld`, `vpsrad` | The `NDD` immediate shifts: one opcode (72) with three extensions, so a wrong `/digit` gives the wrong shift direction. Counts 1, 11 and 31 |
| 11 | `vpslld` from memory | The same shift as slot 7 with the source in memory. If 7 and 11 disagree, the memory form of the `NDD` encoding is wrong |
| 12, 13 | `vpsllvd`, `vpsrlvd` | Per-lane variable shifts, one with the count vector in a register and one in memory |
| 14 | `vpaddd {k1}` | Merge masking. KNC has no zeroing mask, so a clear bit must leave the destination lane untouched |
| 15 | `vpslld zmm17 {k2}` | Destination above `zmm15`, which clears `V'` (P2 bit 3) while `aaa` stays, in the encoding least able to be cross-checked |

Two passes run with different second operands. Pass 1 uses shift counts
from 0 to 33, so the variable shifts see both valid counts and the "above
31 gives zero" rule. Pass 2 uses full 31-bit patterns, which gives the
bitwise operators real bit coverage and drives every variable shift past
31, the other half of the same rule. Counts are kept non-negative because
the document does not say what a negative count does, and a test should
not guess.
