# knc_test.c

Conformance for every kernel in `libknc`: 32 widths, two directions, 64
kernels, on the card. Nothing on the host can execute MVEX bytes, so this is
the only place the library is checked.

```sh
phi put card/lib/knc/knc_test.c /tmp/knc_test.c
phi run sh -c 'cd /tmp && cc -O2 -o knc_test knc_test.c -lknc && ./knc_test'
```

## Why a round trip is not enough

`knc_pack` followed by `knc_unpack` returning the original values proves
only that the two agree. They are generated by the same code from the same
idea of the layout, so they would agree just as happily if that idea were
wrong.

So the test carries an independent scalar model of the layout, written
straight from the definition, and crosses it with the kernels in both
directions:

| Check | Catches |
| --- | --- |
| scalar pack, `knc_unpack` | an unpack kernel that reads the wrong bits |
| `knc_pack`, scalar unpack | a pack kernel that writes the wrong bits |
| `knc_pack`, `knc_unpack`, and the packed bytes compared with the scalar packer's | the two kernels agreeing on a layout the model does not share |

The third one is the one that matters: it reports `BYTES DIFFER` when a
block decodes correctly but was not encoded the way the model encodes it,
which is the failure a round trip cannot see.

Values are a mixing step masked to the width, with zero and the all-ones
value placed at the first, second and last positions and at the start of
lane 0's second position, so an off-by-one at either end of the range or at
a lane boundary shows up.

Two more checks follow the table: that an out-of-range width writes nothing
rather than taking a computed jump somewhere, and that `knc_memcpy64`
matches `memcpy`.
