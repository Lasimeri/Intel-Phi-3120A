# QuickJS

`docs/decisions/0004`: QuickJS is the JavaScript runtime on the card,
because Bun needs SSE4.2 and a JIT, and V8 needs SSE2. QuickJS is pure C,
interpreter only, ES2023.

`quickjs.sh` cross-builds Bellard's QuickJS 2026-06-04 against musl with
`knc-cc`, static, with the `knc` module compiled in so JavaScript reaches
the vector unit. It installs `qjs`, `qjsc`, `libquickjs.a` and the headers
under `/opt/phi`.

```sh
card/lib/knc/build.sh                      # libknc.a into the sysroot first
card/userland/components/quickjs.sh
phi put ~/.cache/intel-phi-3120a-build/userland/quickjs/phi-quickjs.tar.gz /tmp/q.tar.gz
phi run sh -c 'tar -xzf /tmp/q.tar.gz -C /'
phi run qjs -e 'console.log("hello")'
```

## Three things the build has to do that upstream does not

**`LDFLAGS="-static"`.** `knc-cc` does not add `-static` (the kernel build
needs it not to), and QuickJS's Makefile does not either, so left alone this
links a dynamic PIE. That fails on `libknc`'s function tables, which are
absolute 64-bit relocations, long before it would fail on the card having no
dynamic loader. The error is `relocation R_X86_64_64 cannot be used against
symbol 'knc_unpack_b1'; recompile with -fPIC`, which is misleading: the fix
is not `-fPIC`, it is not building a PIE.

**The PAUSE guard.** `Atomics.pause()` reaches for PAUSE through inline
assembly guarded on `__x86_64__`; KNC deletes PAUSE (ISA reference
327364-001, appendix B.2). The build adds `&& defined(__SSE2__)` to that
guard, which sends this card to the empty no-op `quickjs.c` already has for
other architectures and changes nothing elsewhere. Without it the audit
reports one illegal instruction in `js_atomics_pause`.

This is the third dialect of the same portability bug in this project. xz
guarded CMOV assembly on `__x86_64__` (`xz.md`); zstd used function-level
target attributes with CPUID dispatch (`zstd.md`); this is inline assembly
again. All three assume x86-64 implies a feature set, and none is visible in
a build log.

**The module object.** QuickJS has no way to add an object to `QJS_OBJS`
from the command line, so `qjs_knc.o` is compiled by hand and passed through
`EXTRA_LIBS`, which the Makefile appends to the link line. An object there
links the same way. One line is inserted into `qjs.c`'s
`JS_NewCustomContext`, beside where it already registers `std` and `os`.

`CONFIG_LTO` is off, as ADR 0004 says. The `-mno-*` set and
`-fno-jump-tables` come from `knc-cc` itself.

## Self-hosting build step

`repl.c` is generated by running `qjsc` on `repl.js`, and `qjsc` is a card
binary. That works because a card binary is an ordinary x86-64 executable
minus some instruction set extensions, so the host runs it: the same
property `cpython.sh` relies on. Nothing needs a separate host build of
QuickJS.

## Verified 2026-09-20

`qjs` and `qjsc` both audit clean (0 illegal; 19848 KNC vector instructions,
which is `libknc` having been linked in). `card/lib/knc-js/knc_demo.js` runs
on the card: all 32 bit widths round-trip against a scalar model, and decode
reaches 398.9 M values per second at 11 bits, about 1 percent below C.

`qjs_knc.md` covers the module itself.
