# x86_64-knc-linux-musl.json

Custom Rust target for the card, generated by `gen-target.sh` from the
built-in `x86_64-unknown-linux-musl` spec of the installed rustc. Changes
against that base:

| Field | Value | Why |
| --- | --- | --- |
| `features` | `-sse`, then MMX, CMOV, NOPL, MOVBE, POPCNT, LZCNT, BMI1, BMI2, XSAVE, CMPXCHG16B, PRFCHW, CLFLUSHOPT, RDRAND, RDSEED, ADX, FSGSBASE, PCLMULQDQ, AES, SHA off; `+x87` | The deletion list (`docs/research/isa-deletions.md`). Rust feature names where rustc has them (it maps `bmi1`, `cmpxchg16b`, `rdrand`, `pclmulqdq` to LLVM's `bmi`, `cx16`, `rdrnd`, `pclmul`); names rustc does not know (`cmov`, `nopl`, `mmx`) pass through to LLVM unchanged. |
| `cpu` | `x86-64` | The baseline; the feature string overrides its implications. Requires the patched LLVM so that `-cmov` is honored in 64-bit mode and `f64` returns use `ST0`. |
| `max-atomic-width` | 64 | No `CMPXCHG16B` (the musl base already says 64). |
| `panic-strategy` | `abort` | Unwinding on the card is untested; `libunwind.a` exists for backtraces only. |
| `vendor` | `knc` | `cfg(target_vendor = "knc")` gates card-specific code. |
| `crt-static-default` | true | Static binaries until the musl dynamic loader is validated on the card. |

## Why `-sse` and not `-sse2`

rustc refuses a spec that names `sse2` as disabled: its x86-64 hard-float
ABI model requires `x87` and `sse2` (`Target::abi_required_features`), and
the only alternative ABI, `x86-softfloat`, requires `soft-float`, which
would break float FFI with musl and clang (ADR 0002). The check looks at
the names written in the spec; `-sse` is not on its list, and rustc's own
reverse implication then disables `sse2` through `avx512*` everywhere
(`cfg(target_feature)` and the backend feature list). The compiler prints,
once per crate:

    warning: target feature `sse2` must be enabled to ensure that the ABI of the current target can be implemented correctly

This is expected (rust-lang/rust#116344, a future-incompatibility notice).
ADR 0007 names the escape hatch for the day it becomes an error.

Verified with `rustc --print cfg --target x86_64-knc-linux-musl.json`: the
only target features listed are `x87`, `fxsr`, `crt-static`.

## Regenerating

`gen-target.sh` (see `gen-target.md`), after every rustc upgrade. Field
names and types change between releases (`target-pointer-width` became a
number in 1.98).

## Building

`toolchain/rust/build-std.sh` does it for the check crate. For any other
crate, copy `toolchain/check/hello_rs/.cargo/config.toml` (target path,
`build-std`, `knc-cc` as linker) and run

    LD_LIBRARY_PATH=toolchain/build/llvm-dylib/lib RUSTC_BOOTSTRAP=1 cargo -Zjson-target-spec build --release

Link the result with `knc-cc ... -lunwind` (see `toolchain/libunwind/`).
